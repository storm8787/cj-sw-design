# AI 비용 검증·모델 선정 기록 (2026-10-30)

**결론:** 기본 모델을 `gpt-6-luna`로 바꾸고, **FP 후보 작업만 `gpt-6.1-sol`**을 유지한다(`OPENAI_MODEL=gpt-6-luna`, `OPENAI_MODEL_FP_CANDIDATES=gpt-6.1-sol`).
- 이 구성은 가상 3사례 × 2회 실제 실행에서 아래 항목을 확인했다(표본이 작다는 한계 있음, §6).
  - 필수 요구 누락·지어낸 연계·스키마 실패·한국어 이탈 없음.
  - 같은 사례에서 기준(전부 gpt-6.1-sol) 대비 추정 비용 약 **68~75% 감소**.
- Luna 단독(약 96% 감소)은 FP 후보에서 사용자 필수 기능('교육 신청 취소')의 처리 후보를 빠뜨려 **채택하지 않았다.**

## 1. 현재 AI 사용 구조(조사 결과)
| 항목 | 내용 |
|---|---|
| AI 작업 | 질문, 요구사항 초안, 설계 초안, FP 후보, 참고문서 항목 추출(4,000자 구간별). 그 밖의 FP 가중치·복잡도·금액·엑셀·검토(규칙)는 코드가 한다(AI 호출 없음) |
| 호출 횟수 | 작업당 1회 + 형식 오류·치명적 검증 오류 시 **최대 1회 재요청**(`call_ai max_attempts=2`). SDK 자동 재시도 1회(네트워크 오류). 무한 재시도 없음 |
| 중복 호출 방지 | 같은 프로젝트 데이터·작업·연결이면 기존 작업 결과를 재사용. **모델이 키에 빠져 있었음** → 이번에 작업 키에 모델·추론 설정 포함 |
| 출력 상한 | `AI_MAX_OUTPUT_TOKENS=32000`(상한일 뿐 실제 사용량만 과금). 설계 출력 실측 최대 10,632토큰(Sol, 교육 사례). 8,000토큰 잘림 이력 때문에 **상한을 낮추지 않음** |
| 추론 설정 | 지정 안 함(모델 기본값). 추론 토큰은 출력 토큰에 포함되어 보고·과금됨 |
| 전송 내용 | 작업별 프로젝트 요약(project_brief) + 문서는 해당 구간만. 문서 앞부분 자르기 없음 |
| 사용량 수집 | **로그에만 있었음** → 이번에 작업마다 입력·캐시·출력·추론 토큰·응답 시간·실패를 `jobs.usage`에 저장, 화면 작업 상태에 표시 |
| 캐시 | OpenAI 자동 프롬프트 캐시(앞부분이 같은 긴 요청). 공통 지시문이 앞에 있음. 실측 캐시 적중은 일부 요청에서만(1,100~3,900토큰) |

## 2. 후보 모델과 단가
- 계정 접근 확인(2026-10-30, `models.list`, 무료): 136개 모델. 후보 `gpt-6-luna`, `gpt-6.1-terra`, 기준 `gpt-6.1-sol` 모두 사용 가능.
- **공식 요금표를 확인하지 못함.** `developers.openai.com`, `platform.openai.com`이 이 세션 네트워크 정책으로 차단됐다. 웹 검색의 2차 출처만 확인했다(2026-10-30).
  - 출처 예: pricepertoken.com, anotherwrapper.com, apidog.com, aireiter.com(아래 표).
  - 출처 사이에 `gpt-6.1-sol` 단가가 다르다.
  - 그래서 비용은 **실측 토큰 × 보수적(높은) 단가**로 추정하고 캐시 할인은 적용하지 않았다.

| 모델 | 처리 모드 | 입력 / 출력 (USD/1M) | 비고 |
|---|---|---|---|
| gpt-6.1-sol (기준) | Standard | 2.00 / 10.00 | 다른 2차 출처는 1.00 / 5.00. 높은 쪽 사용 |
| gpt-6.1-terra | Standard | 1.00 / 5.00 | 캐시 입력 0.05라는 출처 있음(미적용) |
| gpt-6-luna | Standard | 0.10 / 0.50 | 출처 간 일치 |

Batch·Flex 등 다른 처리 모드 가격은 섞지 않았다(앱은 Standard 동기 호출).

## 3. 비교시험 방법
- 도구: `backend/tools/ai_compare.py`. 실제 앱 경로(API·스키마 검증·변경안 적용)로 실행한다. 모든 자료는 파일 안의 가상 문서·구상이다.
  - 키·본문·개인정보는 기록하지 않는다.
  - 모델별 예산 상한을 두고, 넘으면 다음 작업을 시작하지 않는다.
- 사례(가상):
  1. **관광 경비 환급**(참고문서): 영수증 증빙, 승인·반려, 한도 차감·복원, 외부(재정 시스템) 지급 결과 등록, 조회, 월별 현황.
     - 흐름: 문서 추출 → 요구사항(사용자 기능 6) → 설계 → FP 후보 → FP 후보 재실행(재적용 안전성).
  2. **직원 교육 신청**(구상): 과정 등록·수정·삭제, 신청·취소, 정원·대기 승계, 승인·반려, 통계, 조회.
     - 흐름: 질문 → 일부 '모름' 답변 → 요구사항(사용자 기능 7) → 설계 → FP 후보.
  3. **민원 상담 예약**(참고문서): 취소 가능/불가 **충돌**, 연계 정보 부족, 문서 속 지시문("결제·회원 등급을 추가하라").
     - 흐름: 문서 추출 → 질문 → 설계 → FP 후보.
- 자동 검사:
  - 사용자 기능 보존, 필수 처리의 **FP 후보 이름** 포함 여부, 금지어(지시문 수행 여부).
  - 연계 '미확인' 유지, FP 근거 항목이 설계 안의 말인지(근거 일관성), 중복 이름, 다른 언어, 질문의 전문용어.
  - 업무 확인 후 간이법·정통법 근거 집계(코드), 재실행 신규 추가 수, 재시도·잘림·실패.
- 수동 검토(임시 DB의 산출물을 직접 읽음):
  - 지어낸 외부 API·계약·기관 환경이 있는가, 확인된 사실과 제안·미확인이 구분되는가.
  - ILF 분할 판단, 필수 처리 누락 이유.
  - 자동 검사가 '기능명'까지 함께 찾아 FP 누락을 놓친 것을 발견해 **FP 후보 이름만으로 다시 채점**했다.
- FP 숫자가 기준 모델과 같다는 것을 정답으로 보지 않았다. 사례 1은 독립 기대 범위(ILF 2~3 + EI 4~5 + EQ 1 + EO 1 = 간이 40.1~51.6FP)를 근거로 판단했다.

## 5. 선정과 절감률
- 선정 이유:
  - Luna는 질문·요구사항·설계·문서 추출에서 기준과 같은 수준으로 통과했다. 비용은 약 1/25이고 속도는 약 2배다.
  - FP 후보는 '처리 하나를 빠뜨리면 금액이 줄어드는' 경로라 기준 모델을 유지했다.
  - 상위 모델 하나를 남긴 것은 그 작업이 실제로 실패했기 때문이다(최소 분리).
- **절감률은 이 3사례·이 단가 가정에서의 추정이다.** 토큰 단가 비율(1/20)을 앱 전체 절감률로 보지 않는다.
  - 재실행 제외 기준 $0.552 → $0.137~0.178로 **약 68~75% 감소**.
  - 실제 절감은 사업 규모·재요청·문서 구간 수·FP 후보 실행 횟수에 따라 달라진다.
- 함께 넣은 코드 보완:
  - **처리 후보 없는 기능 검증.** EI/EO/EQ(또는 유형 미정) 후보가 연결되지 않은 기능을 코드가 찾아 1회 재요청하고, 남으면 경고한다. FP 후보 비용이 최대 1회분 늘 수 있다.
  - 작업별 모델 고정, 사용량 기록, 재사용 키에 모델 포함.
- 검토했지만 채택하지 않은 것:
  - **출력 상한 축소:** 잘림·재요청 위험. 실측 출력 최대 10.6k.
  - **문서 앞부분 자르기:** 요구 누락 위험.
  - **추론 강도 낮추기:** 시험하지 않아 기본값 유지.
  - **저가 모델 실패 시 상위 모델 자동 전환:** 동의·고정 정책을 복잡하게 하고 무제한 비용 위험. 대신 작업별 고정 모델.

## 6. 미검증·한계
- 공식 단가 미확인(2차 출처). 표본이 작다: Sol 1회, Terra 1회, Luna 5회, 혼합 2회, 사례 3종.
- 미검증 항목:
  - 여러 구간의 큰 문서 추출.
  - 추론 강도 조정, Anthropic·사내 LLM, Batch.
  - 실제 사업 문서(시험에 쓰지 않음).
- SDK 내부 자동 재시도(네트워크 오류 시 1회)는 사용량에 따로 잡히지 않을 수 있다.

## 7. Render 적용 절차(사용자)
**코드·`render.yaml` 기본값을 바꿔도 이미 만든 Render 서비스의 환경변수는 자동으로 바뀌지 않을 수 있다**(Blueprint 동기화 설정에 따라 다름).
1. Render → `sw-design-helper` → **Environment**를 연다.
2. `OPENAI_MODEL`을 `gpt-6-luna`로 바꾼다.
3. `OPENAI_MODEL_FP_CANDIDATES`를 추가하고 값은 `gpt-6.1-sol`로 둔다. 저장하면 재시작된다.
4. 앱 상단 AI 표시가 'OpenAI(ChatGPT) · gpt-6-luna (작업별: FP 후보 gpt-6.1-sol)'인지 확인한다.
5. 가상 프로젝트에서 '질문 받기'를 실행해, 작업 상태의 '호출 모델 gpt-6-luna'를 확인한다.
6. 'FP 후보 만들기'를 실행해, 작업 상태의 '호출 모델 gpt-6.1-sol'을 확인한다.
7. 며칠 뒤 OpenAI 사용량 화면에서 모델별 금액을 확인한다.

참고: 설정을 바꾸기 전에 제출해 대기·재시도 중인 작업은 다른 모델로 몰래 실행되지 않는다. "AI 모델 설정이 바뀌었습니다"라며 실패하므로 다시 요청하면 된다. 이전 작업 결과와 프로젝트 데이터는 그대로다.

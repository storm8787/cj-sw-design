# 엑셀 산출물 서식 (2026-10-30 개편)

다운로드 엑셀을 **산출내역서처럼 훑고 인쇄할 수 있는 업무용 서식**으로 바꿨다. 생성 코드는 `backend/app/excel/export.py`이고, 신규·기존 프로젝트의 모든 다운로드와 시연판 샘플에 같은 코드가 쓰인다.

## 참고한 것과 채택하지 않은 것
- 참고 파일: 사용자가 준 '4. 산출내역서_FP_…V1_1_20260305.xlsx'. 원본은 작업 폴더 밖에서만 읽었고 저장소에 넣지 않았다.
- 서식 관찰 결과(openpyxl로 직접 확인):
  - **FP금액 시트:** 제목(맑은 고딕 14pt), 기준 표시, '(단위 : 원)'. 구획은 '○ 개발원가 산정 / ○ 직접경비 / ○ 보정계수 산정 / ○ FP 집계'.
  - **FP산정(간이법) 시트:** 다단 머리글(①애플리케이션명 ②세부 업무명 ③단위프로세스명 …). 인쇄 영역 A1:H22, 반복 머리행 2:4.
  - **공통:** 머리글·제목은 연노랑 채움(팔레트 43 = FFFF99), 소계·총액은 회색(22 = C0C0C0). 눈금선을 숨기고 A4 세로로 인쇄.
- 채택한 것:
  - 구획 구성과 머리글 구조.
  - 연한 채움, 테두리, 총액 강조, 천 단위 금액 서식.
  - A4 인쇄, 반복 머리행.
- **채택하지 않은 것:**
  - 사업명·고도화 문구·업체 정보.
  - FP 단가 553,114원, 할인·이윤·보정값, 원본 FP 건수·금액.
  - 노임단가 방식.
  - 원본의 깨진 이름 정의(#REF!), 12,875행 사용 영역, 빈 병합 영역.
  - 원본 수식. 수식은 앱 계산 엔진과 같은 기준으로 새로 만들었다.
  - 깨진 글꼴명. '맑은 고딕' 하나만 쓴다.

**기준값·산식·끝수 처리는 바꾸지 않았다**(FP_RULES §3~5 그대로).

## 공통 서식·인쇄 규칙
- **글꼴·크기:** 맑은 고딕. 제목 15pt, 구획 11pt, 표 10pt, 보조 8~9pt.
- **채움:** 머리글 FFF2CC, 항목명 F2F2F2, 소계·총액 D9D9D9, 참고값 DDEBF7, 경고 FCE4E4. 상태는 색만으로 구분하지 않고 문구를 함께 쓴다.
- **숫자:** 금액 `#,##0`(단위 원 표시), FP `#,##0.0`, 보정계수 `0.0000`/`0.00`, 비율 `0%`.
- **정렬:** 금액·FP는 오른쪽. ID·유형·상태는 가운데. 긴 설명은 왼쪽 줄바꿈이며 행 높이는 자동.
- **병합:** 제목·구획·요약 표에만 쓴다. FP 상세·요구사항 등 데이터 행에는 병합하지 않는다(필터·정렬·행 증가 보존, 테스트로 확인).
- **인쇄:**
  - 눈금선 숨김, A4. 가로 폭만 1페이지에 맞추고 세로는 자연스럽게 나눈다(fitToHeight=0).
  - 머리행 반복, 바닥글 '쪽 / 전체쪽'과 시트명.
  - 인쇄 영역은 **실제 마지막 행·열까지** 동적으로 잡는다.
- **틀 고정·필터:** 표 시트마다 머리행 아래에서 틀을 고정한다. 필터는 데이터 행 범위에만 건다.

## 산식·검산 보존
- 개발비 수식 경로는 같다: `총FP × 단가 × 규모 × 연계 × 성능 × 운영환경 × 보안 × 단계비율 → 끝수 → 이윤(끝수) → + 직접경비 → 부가세(끝수) → 총액`.
  - 총FP 칸은 FP 유형별 집계 합계를 수식으로 참조한다.
  - 직접경비 칸은 직접경비 표의 합계를 수식으로 참조한다.
- 'Python 확인값' 열은 각 시트에서 빼고 **검산 시트에 모았다**.
- 검산 항목이 늘었다(사례당 13개 안팎 → 22~33개). 간이법·정통법 유형별 FP·기능 수, 직접경비가 새로 검산된다.
- 확인 방법(2026-10-30 실행):
  1. 서식 변경 전 main 코드와 변경 후 코드로 같은 가상 프로젝트 4종을 만들었다.
     - 간이법 완료 + 목표예산.
     - 정통법 완료(끝수 10원 반올림).
     - 전체 초안·미분류(견적 없음).
     - 긴 설명 + FP 115행 추가 + 직접경비 3건 + 견적 2개 + 시나리오.
  2. 요구사항·기능·FP ID와 연결, FP 점수·복잡도·집계 여부, 간이·정통 합계, 산정 상태, 견적 총액·공급가·개발원가, 시나리오 금액·조정률을 비교했다. **차이 0**, 엑셀 안 ID 누락 0.
  3. LibreOffice로 재계산했다. 4종 모두 검산 '일치'(22~33항목), 오류값(#REF!·#VALUE! 등) 0.
  4. LibreOffice로 PDF를 만들어 첫 시트·개발비·FP 간이법·정통법 쪽을 이미지로 직접 확인했다.
     - 확인한 것: 머리행 반복, 줄바꿈, 미실행 표시, 열 폭.
     - 고친 것: 보정계수 수준 번호 중복, 좁은 열의 머리글 줄바꿈.
- 서식 회귀 테스트는 `backend/tests/test_excel_format.py`다.
  - 확인 항목: 인쇄 영역·방향·머리행 반복·눈금선·글꼴, 데이터 행 병합 없음, 총액 수식·강조, 빈 프로젝트.
  - 개편 중 빈 프로젝트(FP 0건)에서 틀 고정 위치가 병합 셀에 걸려 생성이 실패하던 문제를 이 테스트가 잡아 고쳤다.

## 확인하지 못한 것
- 실제 Microsoft Excel에서 연 화면과 인쇄 미리보기.
  - LibreOffice로만 확인했다. 행 높이 자동 맞춤·쪽 나눔은 Excel에서 약간 다를 수 있다.
  - 이 환경에는 맑은 고딕이 없어 PDF는 대체 글꼴로 그려졌다.
- 사용자의 실제 프로젝트 파일은 확인하지 않았다(가상 사례만 사용).

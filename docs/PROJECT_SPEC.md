# PROJECT_SPEC — 정보화 설계 도우미 확정 요구사항

- 최초 확정: 2026-10-29 (사용자 최초 지시 원문 기준 정리)
- 이 문서는 요구사항 전체와 기능별 완료 조건을 보존한다. 구현 현황은 `docs/HANDOFF.md`의 표를 본다.
- 요구 ID(SPEC-xx)는 HANDOFF·VALIDATION에서 참조한다. 임의로 삭제·축소하지 않는다.

## 0. 범위

| 구분 | 내용 |
|---|---|
| 이번 대상 | ⑥ 홈페이지·포털 신규개발, ⑦ 일반 SW·정보시스템 신규개발 (웹, 데스크톱, 서버 프로그램, 배치 자동처리, 시스템 연계 포함) |
| 포함 | 신규개발에 필요한 데이터·연계 설계, HW·SW 구성 추천(설계 보조) |
| 제외(후속 확장) | 연간 SW 유지관리, 장비 유지관리, ITS/BIS, RFID, 단독 DB·공간정보 구축, 컨설팅 |
| 금액 제외 | 장비 구매비. 별도 유료 SW·서비스 필요성은 표시만 하고 개발비에 자동 합산하지 않음 |
| 사용자 | 지방자치단체 공무원(업무 목적은 알지만 설계·FP·기술 구성에 익숙하지 않음) |

## 3. 사용자 기능

### A. 프로젝트 관리 (SPEC-A1 ~ A6)
- A1 생성·목록·이름 변경·저장·이어하기
- A2 사업유형 홈페이지·포털/일반 정보시스템 구분(설계 흐름 공유)
- A3 시작 방식: 구상 기반 / 참고문서 기반
- A4 금액 조건: 예산 미지정 / 개발비 지정 (시작 방식과 독립)
- A5 금액 조건 선결정: 부가세 포함 여부, 포함 단계(분석·설계·구현·시험)
- A6 삭제는 확인 절차(프로젝트명 재입력) 후, 다른 프로젝트에 영향 없음
- 완료 조건: API·화면 동작, 삭제 시 다른 프로젝트 데이터·파일 보존 테스트

### B. 구상 기반 설계 (SPEC-B1 ~ B7)
- B1 "교육 신청·관리 프로그램이 필요하다" 수준 한 줄로 시작 가능
- B2 생각한 기능을 자유문장·목록·표(탭 구분)로 입력
- B3 목적·이용자·업무절차·권한·데이터·연계·처리량·비기능을 단계적으로 보완
- B4 질문은 소수(기본 최대 5개)씩, 선택지·직접입력·모름/나중에 결정 지원
- B5 모름 선택 시 권장안과 이유를 제시하고 '가정'으로 기록
- B6 시스템 목적에 따라 질문 생성(교육 질문을 모든 사업에 고정 적용 금지)
- B7 빠진 기능·비기능 제안, 원래 요청과 AI(또는 샘플 규칙) 제안 구분
- 완료 조건: 교육 신청 시스템과 다른 유형(예: 민원 접수·배치 연계 시스템)에서 서로 다른 질문이 생성됨을 테스트

### C. 참고문서 기반 설계 (SPEC-C1 ~ C8)
- C1 타 기관 과업지시서·RFP·설계서·FP 산정표 업로드
- C2 문서별 요구사항·업무·기능·데이터·연계·조건 추출, 원문 위치 보존
- C3 우리 기관 기준 유지/수정/제외/추가 확인(기관명 치환만 하지 않음)
- C4 타 기관 예산·기간·개인정보·특정 제품 조건은 자동 확정값이 되지 않음('참고값' 표시)
- C5 원문 대비 변경 내역과 이유 제공
- C6 PDF, HWPX, DOCX, XLSX, TXT, MD 우선 지원 + 파일별 추출 품질 표시
- C7 HWP: 사용 가능한 파서 확인 후 지원, 불가 시 HWPX/PDF 변환 안내·재업로드, '지원 완료'로 표시하지 않음
- C8 스캔 PDF·이미지 표·암호화·손상·표 병합 탐지 표시, OCR 미구현이면 읽은 척 금지, 장문 분할·중간 저장, 일부만 읽고 완료 표시 금지
- 완료 조건: 형식별 추출 테스트, 스캔/암호/손상/장문 처리 테스트

### D. 설계 작업대 (SPEC-D1 ~ D5)
- D1 요구사항, 업무흐름, 기능 상세, 화면, 데이터·관계, 연계, 비기능, 검수 기준 편집
- D2 과업지시서 초안: 사업 개요·목적·범위·상세 요구사항·일정·산출물·검수 기준
- D3 확인하지 않은 DB·API·기존 시스템 구조를 사실처럼 확정하지 않음('확인 필요' 표시)
- D4 "왜 필요한가", "분류 근거" 확인 가능
- D5 FP 용어 한국어 설명·예시

### E. FP 산정 (SPEC-E1 ~ E8)
- E1 간이법·정통법 모두 실제 다른 계산 경로
- E2 공식 기준의 경계·단위프로세스·데이터 기능·유형 식별·중복 판단·가중치 반영
- E3 정통법은 DET/FTR/RET·복잡도 표 사용, 누락 시 추가 질문 또는 명시적 가정, 확정 표시 금지
- E4 메뉴·화면·버튼·테이블 수를 FP 개수로 간주하지 않음
- E5 사용자·관리자 동일 기능 자동 이중 계산 금지(중복 의심 표시)
- E6 AI는 후보·근거·불확실성을 구조화 응답으로, 사용자 확정 후 코드로 점수 계산
- E7 요구사항 포함·누락, 미확정, 중복 의심, 비기능 항목 표시
- E8 산정 근거 열람·수정(점수 덮어쓰기 대신 분류·입력·복잡도 수정)

### F. 개발비·목표금액 (SPEC-F1 ~ F8)
- F1 기준 산정과 목표예산 시나리오를 별개 버전으로 관리
- F2 목표예산 모드에서 기능 삭제·축소·추가 금지(시나리오는 기준과 동일 FP 항목 집합)
- F3 예산 대응 환산값·조정률·차이 별도 표시, 공식 측정 FP와 구분
- F4 기준 금액, 목표 금액, 차이, 조정 방식, 최종 참고 금액 표시. 목표액 일치·원 단위 끝수 처리 명시·검증
- F5 기준 판본·적용일, 단계별 범위, 단가, 보정계수, 직접경비, 이윤, VAT, 끝수 규칙 설정·기록
- F6 Decimal 계산, 구성요소별 계산 근거
- F7 장비 구매비 제외, 유료 SW·서비스는 표시만
- F8 견적은 적용 기준 스냅샷을 포함해 나중에 열어도 당시 기준 보존

### G. 기존 문서 검토 (SPEC-G1 ~ G5)
- G1 업체 과업·설계·FP·금액 문서 대조
- G2 요구사항 누락, 불명확 범위, 문서 간 불일치, FP 중복·분류 의심, 산식·계수·합계·VAT, 미확인 연계
- G3 판정: 확인 일치/차이 발견/확인 필요/근거 부족 (정보 부족을 오류로 단정 금지)
- G4 원문 위치, 이유, 수정안, 업체 질문
- G5 실제 성능·연계·보안 충족은 문서로 확정 불가 표시(자료 일치 검토 ≠ 시스템 검증)
- 완료 조건: 가상 문서에 심은 합계 오류·중복·누락을 근거와 함께 탐지하는 테스트

### H. HW·SW 추천 (SPEC-H1 ~ H6)
- H1 기존 서버·OS·DB·라이선스, 내부/외부망, 운영 인력, 구축 방식, 이용자·동시접속·데이터 증가·연계 질문
- H2 자체 서버: 입력 가정 근거 CPU·메모리·저장공간·역할 분리 구성안, 확정 용량·성능 보장 금지
- H3 클라우드: 인스턴스 사양(CPU/RAM) 추천 제외, 서비스 구성·저장·백업·운영 방식 제시
- H4 SW: OS·웹/WAS·DB·프레임워크·부가 SW의 호환성·라이선스·지원 상태·운영 난도 비교
- H5 '최신 추천'에는 공식 URL·확인일·확인 버전/지원 상태. 미확인 시 '현재 상태 미확인'
- H6 외부 자료는 허용 URL 서버 측 조회 또는 수동 등록, 내부 주소·클라우드 메타데이터 조회 차단

## 4. 엑셀 산출물 (SPEC-X1 ~ X5)

  개발비_기준, 목표예산_시나리오, 검토의견, HW_SW추천, 근거_변경이력 (+ 검산 시트 허용)
- X2 미실행 기능 시트는 '미실행' 표시, 미분류 항목은 빈칸이 아닌 '미분류'로 표시

- X4 화면·서버·엑셀 금액·FP 일치. Python 계산 확인값 + Excel 수식 제공, 캐시값 없는 수식을 계산 완료로 보고하지 않음

## 5. 화면·저장·운영 품질 (SPEC-Q1 ~ Q12)
- Q1 시작 화면: 새 설계 / 참고문서로 설계 / 기존 문서 검토 / 프로젝트 이어하기
- Q2 프로젝트 단계: 개요 → 자료·질문 → 요구사항 → 설계 → FP·개발비 → 검토·추천 → 엑셀, 자유 이동
- Q3 표 직접 수정, 변경 전후 비교, 단계별 저장, 미확정 수, 다음 필요한 입력

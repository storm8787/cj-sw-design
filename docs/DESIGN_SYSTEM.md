# 디자인 시스템

## 목적과 참고 확인 (2026-10-30)
처음 사용하는 공무원이 현재 행동을 먼저 파악하고, 필요한 순간에 상세 근거를 확인한다.
토스의 간결한 행동 안내, 애플의 여백·타이포그래피라는 **사용자 요청 방향**을 적용한다.
이 환경에서 toss.im, apple.com/kr, 공개 Pages 주소는 프록시 403으로 열리지 않았다. 홈페이지 화면을 직접 확인한 결과로 설명하지 않는다.
실제로 읽은 자료: [토스 공식 Frontend Fundamentals](https://github.com/toss/frontend-fundamentals) README(raw 파일 HTTP 200). 접근성·유지보수 원칙을 참고했다. 브랜드의 시각 가이드를 검증한 자료는 아니다.
디자인 선택: 선택지 세 개 → 이름/구상 입력 → 단계별 작업 → 비교/근거 확인. 페이지 상단에는 제목·실행 상태·핵심 다음 입력을 배치한다.

## 구성 요소와 문구
- `Frame.Header`: 브랜드·모드·인증 상태·본문 건너뛰기를 공유한다.
- `Frame.Dialog`: native dialog + portal. 데스크톱 모달, 모바일 하단 시트. Esc·닫기·Tab 순환·포커스 복귀. 화면 밖을 누르면 닫는다. 모바일 키보드는 실제 기기 확인 필요.
- `Frame.Skeleton`: 실제 데이터를 기다리는 동안만 표시. 시연 데이터를 일부러 지연하지 않는다.
- `Workspace`: 현재 단계 aria-current, STEP n/7, 이전/다음 이동, 핵심 입력 1건과 전체 목록. 상태 카운트는 추가 입력 안내이며 검수 완료를 보장하지 않는다.
- 서버 저장 버전, 처리 중, AI JobStatus, 미확정/재검토 칩을 구분한다. 개요 수정 시 미저장 경고와 이동 확인. 다른 단계는 기존 명시적 저장/적용을 유지한다.
- `EditableTable`: PC 비교 열 보존, 상태 칩 필터·검색·결과 건수, ID 클릭 상세 근거. 모바일은 표 내부 가로 스크롤, 상세는 시트. 원본·연결 ID·분류 근거는 삭제/요약하지 않는다.
- `Help`: 전문용어의 짧은 정의와 예시를 같은 Dialog로 제공한다.
- 짧은 성공 피드백은 role=status. PC 토스트, 모바일 본문 표시로 입력·키보드를 가리지 않는다. 오류는 화면에 남기고 불러오기 오류에는 재시도를 제공한다.
- 문구는 행동 중심: ‘구상으로 시작하기’, ‘참고문서로 시작하기’, ‘기존 문서 검토하기’. 빈 표에는 이유와 다음 행동, 검색 결과 없음은 조건 변경 안내.
- 중요한 외부 전송 동의·확인 필요 경고·변경안 적용 절차는 축약/비활성화하지 않는다.

## 배치와 반응형
- 일반 홈: 세 출발점(구상 강조) + 별도 이어하기 영역. 생성은 dialog/시트에서 한다.
- 시연 홈: A 정상 완료/B 검토 필요 샘플 선택과 다운로드. 실제 생성 기능으로 보내지 않는다. 제한은 지속적인 짧은 표시 + 펼쳐보기.
- 개요: 이름·구상·목적·경계 우선. 이용자·기간·기관 환경·AI 연결은 상세 설정. 금액 조건은 별도 노출.
- 1000px 이하 단계 내비는 가로 스크롤. 700px 이하 카드·폼은 한 열, dialog는 바텀시트. 표는 열을 억지로 좁히지 않는다.
- reduced-motion에서는 애니메이션 제거. 불필요한 FAB, 인위적 대기, 원격 리소스는 추가하지 않는다.

## 변경 범위와 검증
서버 계산/인증/ID/엑셀 생성기는 변경하지 않았다. 새 구조는 프런트 공통 프레임·dialog, 표 검색/상태 필터·읽기 전용 상세 표시뿐이다.
기존 `e2e/demo.cjs`, `flow.cjs`, `reference.cjs` 검사를 보존하고, 바뀐 시작 이름·접힌 링크를 실제 행동에 맞춰 수정했다.
`e2e/ux.cjs`: 1400/820/390px, A/B 7단계, 검색/상태 필터·시트·키보드, 실제 지연 로딩·오류 주입과 복구, 일반 앱 생성·미저장·저장·재접속을 확인한다. 오류 주입 구간은 정상 요청 오류 0건 검사와 분리한다.
Render 배포, 실제 모바일 기기/스크린리더, 유료 AI 호출은 별도 검증 대상이다.

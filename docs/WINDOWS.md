# Windows 시험판 (로컬 실행, 미서명)

직원 PC(Windows 11 x64, 일반 사용자 권한)에서 기존 웹앱을 그대로 실행하는 **시험판**입니다.
Python·Node·Docker·Git·uv를 설치하지 않아도 됩니다. 업무 화면은 웹판과 같은 화면을 기본 브라우저(Edge·Chrome)로 엽니다.
웹판(Render)·읽기 전용 시연판(Pages)은 그대로 유지됩니다.

> **시험판입니다.**
> - 코드 서명을 하지 않았습니다. Windows SmartScreen이나 기관 보안 프로그램이 경고할 수 있습니다. 경고를 없애거나 보안 기능을 끄는 방법은 안내하지 않습니다. 기관 정책에 따라 판단하세요.
> - 설치 마법사, 자동 업데이트, 자동 시작, Windows 서비스는 없습니다.

## 1. 받기
받는 길이 두 가지입니다. **①이 있으면 ①을 쓰세요.**

**① 프로젝트에 등록된 ZIP (권장)**
- 저장소 최상단의 `CJ-SW-Design-windows-x64-<커밋7자리>.zip`과 같은 이름의 `.sha256`.
- 로그인·만료 없이 바로 받을 수 있습니다. 심사 제출본에는 이 방식으로 등록합니다.

**② GitHub Actions artifact (①이 없을 때)**
- Actions → **Windows 시험판** 실행 결과 → artifact `CJ-SW-Design-windows-x64-trial-<커밋>`.
- **GitHub 로그인이 필요하고 14일만 보관**됩니다(공개 Release 아님). 그래서 심사위원 전달 수단으로는 쓰지 않습니다.

artifact(②) 안의 파일:
- `CJ-SW-Design-windows-x64-<커밋7자리>.zip`: 시험판 본체
- `.sha256`: ZIP의 SHA-256
- `build_info.json`: 소스 커밋, 빌드 환경, Python·PyInstaller 버전
- `smoke-report.json`: Windows에서 통과한 검사 목록

- 해시 확인(선택, PowerShell): `Get-FileHash .\CJ-SW-Design-windows-x64-<커밋>.zip -Algorithm SHA256`의 값이 `.sha256` 파일의 값과 같은지 봅니다.
- **커밋이 달라 보이는 경우:** ZIP은 소스 커밋에서 빌드하고, 그 ZIP을 저장소에 추가하는 커밋은 그보다 뒤에 생깁니다.
  그래서 `build_info.json`의 `commit`과 저장소 최신 커밋이 다를 수 있습니다(정상). 실행파일이 어느 소스에서 나왔는지는 `build_info.json`을 기준으로 봅니다.
- 저장소에 ZIP을 등록할 때는 최상단(또는 `release/`)에 둡니다. `dist/`·`backend/dist/`는 `.gitignore`가 무시해 커밋되지 않습니다.

## 2. 압축 풀기와 실행
1. ZIP을 오른쪽 클릭 → **모두 압축 풀기**. 바탕화면·문서 등 쓰기 가능한 곳이면 됩니다(한글·공백 경로 가능). ZIP 안에서 바로 실행하지 마세요.
2. `CJ-SW-Design` 폴더의 **`CJ-SW-Design.exe`** 를 더블클릭합니다. 같은 폴더의 `_internal`은 지우거나 옮기지 마세요.
3. 처음 실행이면 **로그인 비밀번호**(10자 이상)를 정합니다.
   - 공용 기본 비밀번호는 없습니다.
   - 비밀번호는 해시로만 저장합니다. 이 PC의 다른 프로그램·사용자가 웹 화면에 바로 들어오지 못하게 막는 용도입니다.
4. "시작하는 중" 창이 뜨고, 서버가 준비되면 기본 브라우저가 `http://127.0.0.1:<포트>/`로 열립니다. 정한 비밀번호로 로그인합니다.
5. 런처 창에는 실행 주소, AI 상태와 버튼 네 개가 있습니다: **브라우저 열기 / 설정 / 데이터 폴더 열기 / 종료**.

- 서버는 이 PC 안(127.0.0.1)에서만 열립니다. 사내망 공유, 방화벽 예외, 관리자 권한은 필요하지 않습니다.
- 포트는 기본 8765입니다. 이미 다른 프로그램이 쓰고 있으면 빈 포트를 자동으로 고르고, 그 주소를 런처 창에 보여 줍니다. 다른 프로그램을 끄지 않습니다.
- 이미 실행 중일 때 다시 더블클릭하면 새로 띄우지 않습니다. 실행 중인 프로그램인지 확인한 뒤 그 화면을 다시 엽니다.
- 60초 안에 준비되지 않으면 원인과 진단 기록 위치를 알리는 창을 띄우고 끝납니다.

## 3. 종료
- **브라우저 탭을 닫아도 프로그램은 계속 실행됩니다.** 다시 보려면 런처 창의 [브라우저 열기]를 누르세요.
- 끝내려면 런처 창의 **[종료]**(또는 창의 X)를 누릅니다.
  - 서버, DB 연결, 작업 스레드를 정리하고 끝냅니다.
  - 진행 중인 AI·분석 작업이 있으면 먼저 알립니다. 종료하면 그 작업은 '중단됨'으로 기록되고 다음 실행 때 다시 시도할 수 있습니다.
- 강제 종료(작업 관리자 등)해도 다음 실행 때 DB는 그대로 열립니다. 실행 중이던 작업은 '중단됨'으로 바뀝니다. 강제 종료하면 마지막 저장 전 입력은 남지 않을 수 있습니다.

## 4. 데이터 위치와 보호 범위
| 위치 | 내용 |
|---|---|
| `%LOCALAPPDATA%\CJ-SW-Design\data\` | 프로젝트 DB(SQLite), 업로드 원본, 사용자 정의 기준 |
| `%LOCALAPPDATA%\CJ-SW-Design\config\` | 로그인 비밀번호 해시, 포트·모델 설정(`settings.json`), 세션 키·API 키(Windows DPAPI 보호 파일) |
| `%LOCALAPPDATA%\CJ-SW-Design\logs\` | 진단 기록. 비밀번호·키·문서 원문은 기록하지 않음 |

- 프로그램 폴더(압축을 푼 곳)에는 쓰지 않습니다. 폴더를 옮기거나 새 버전 ZIP을 풀어 실행해도 같은 데이터로 이어집니다. 데이터 초기화는 자동으로 하지 않습니다.
- 프로젝트 데이터는 **이 PC에 남습니다.** DB·업로드 원본은 암호화하지 않은 일반 파일입니다.
  - 보호 범위는 Windows 계정 권한과 PC 보안(디스크 암호화 등)을 따릅니다.
  - 실제 사업 문서·개인정보는 기관 보안 지침에 따라 다루세요.
- API 키·세션 키는 DPAPI로 보호해 저장합니다. 같은 PC의 같은 Windows 계정에서만 풀리고, 다른 계정·다른 PC로 복사하면 풀리지 않습니다. 같은 계정으로 실행되는 다른 프로그램까지 막지는 못합니다.
- 웹판(Render)의 데이터를 자동으로 가져오거나 올리거나 동기화하지 않습니다.

## 5. AI 연결(선택)과 비용
- 처음에는 **샘플 모드**(규칙 기반, AI 아님, 외부 전송 없음)로 시작합니다. 시작만으로 외부 AI를 호출하지 않습니다. 개발 PC의 환경변수(OPENAI_API_KEY 등)도 읽지 않습니다.
- 샘플 모드에서도 다음 기능을 쓸 수 있습니다. 결과는 '샘플 모드'로 구분 표시됩니다.
  - 프로젝트 만들기·편집·저장
  - 문서 올리기·추출
  - FP·개발비 계산
  - 검토
  - 엑셀 내려받기
- AI를 쓰려면 런처 **[설정] → OpenAI API 키**에 본인 키를 넣고 [키 저장]을 누른 뒤, 안내에 따라 다시 시작합니다.
  - 입력란은 가려집니다.
  - 키는 DPAPI 보호 파일에만 저장합니다. 브라우저 저장소, 주소, 화면 빌드, 프로젝트 DB, 백업 JSON, 기록에는 넣지 않습니다. 서버는 키 원문을 브라우저로 돌려주지 않습니다.
  - 모델은 권장 구성으로 고정합니다: 기본 `gpt-6-luna`, FP 후보 `gpt-6.1-sol`(`docs/AI_COST.md`, render.yaml·.env.example과 같음).
- **로컬 실행이어도 AI를 쓰면 입력한 업무 내용과 동의한 문서 원문이 OpenAI 서버로 전송되고, 사용한 만큼 사용료가 청구됩니다.**
  - 요청할 때마다 전송 범위를 보여 주고 동의를 받는 기존 절차는 그대로입니다.
  - 키를 저장하거나 프로그램을 시작하는 것만으로는 호출하지 않습니다.
  - OpenAI 결제 화면에서 월 한도를 설정하세요.
- AI를 끄려면 [설정] → [키 삭제] 후 다시 시작합니다. 샘플 모드로 돌아갑니다.
- 연결 오류 안내는 원인별로 다릅니다.
  - 인증서 확인 실패(기관 보안 프록시 등): Windows 인증서 저장소를 사용합니다. 인증서 검증은 끄지 않습니다.
  - 프록시 연결 실패
  - 키 오류
  - 사용량 한도 초과
- 설정을 바꾼 뒤 다시 시작할 때 진행 중인 작업이 있으면 먼저 알립니다. 작업에 기록된 공급자·모델과 서버 설정이 다르면 다른 모델로 몰래 실행하지 않습니다(기존 원칙).

## 6. 백업과 새 버전으로 교체
- 프로젝트별 백업: 웹 화면 **7 엑셀 → JSON 백업 내려받기**(기존 기능, 업로드 원본 제외).
- 전체 백업: 프로그램을 [종료]한 뒤 `%LOCALAPPDATA%\CJ-SW-Design\data` 폴더를 통째로 복사합니다.
- 새 버전으로 바꾸는 순서:
  1. 기존 프로그램을 [종료]합니다.
  2. 새 ZIP을 다른 폴더에 압축 풀고 실행합니다. 데이터는 그대로 이어집니다.
  3. 문제가 없으면 예전 프로그램 폴더를 지웁니다. 데이터 폴더는 지우지 마세요.
- 비밀번호를 잊었으면 런처 [설정]에서 새 비밀번호를 정합니다(같은 Windows 계정). 바꾸면 기존 로그인은 끊깁니다.
- 프로그램을 완전히 지우려면 프로그램 폴더와 `%LOCALAPPDATA%\CJ-SW-Design`을 지웁니다. 데이터 폴더를 지우면 프로젝트도 함께 지워집니다.

## 8. 빌드(개발자용)
대상 PC가 아니라 **빌드 PC(Windows)**에만 Python·Node·uv가 필요합니다.
```powershell
cd frontend; npm ci; npm run build; cd ..\backend
uv sync --frozen --group desktop
uv run --frozen --group desktop python -m desktop.build
```
- 결과: `backend\dist\CJ-SW-Design\`(배포 폴더)와 `CJ-SW-Design-windows-x64-<커밋>.zip`, `.sha256`, `build_info.json`.
- 고정 버전: Python 3.13.14(uv 관리 런타임을 묶음), PyInstaller 6.22.3, truststore 0.10.5, 나머지는 `backend/uv.lock`.
- 검증: `uv run --frozen python -m desktop.smoke --zip <ZIP> --work <작업 폴더> [--e2e]`.
  - ZIP을 새로 풀어 최소 PATH로 실행파일을 띄웁니다.
  - 실행 순서: 첫 실행 → 파서 → 견적·엑셀 → 기존 E2E → 중복 실행 → 재실행 → 폴더 이동 → 포트 충돌 → 강제 종료 → 시작 실패 → 가짜 키 → 창 모드.
- CI: `.github/workflows/windows.yml`(PR·수동 실행, windows-2025 runner). 비밀값을 쓰지 않습니다. 공개 Release는 만들지 않습니다.
- 구조:
  - `backend/desktop/` 런처가 기존 `app.main:create_app`을 한 프로세스의 스레드 하나에서 Uvicorn으로 실행합니다. reload·다중 worker는 쓰지 않습니다.
  - `/__desktop/instance`·`/__desktop/control`(실행 정보 파일의 토큰 필요)만 런처가 처리하고, 나머지 요청은 기존 앱의 인증·CSRF를 그대로 거칩니다.
  - 앱 설정 환경변수는 지운 뒤 런처 값으로 채웁니다: `APP_ENV=production`, `COOKIE_SECURE=false`, `DATA_DIR`=사용자 데이터 폴더.
  - Render(HTTPS)의 `COOKIE_SECURE=true`는 바뀌지 않습니다.
- 시험·자동화용 옵션(직원은 쓰지 않음): `--no-gui --password-file <파일>`, `--quit`, `--set-openai-key-file <파일>`, `--clear-openai-key`, `--no-browser`. 소스 시험에서만 `CJSWD_HOME`으로 데이터 위치를 바꿉니다.

## 9. 검증 상태와 한계
- Windows runner에서 실제로 빌드·실행한 결과는 `docs/VALIDATION.md` §11에 있습니다.
- GitHub Windows runner에는 Python·Node 같은 개발 도구가 깔려 있습니다. 실행파일은 최소 PATH로 띄웠지만, **개발 도구가 전혀 없는 실제 직원 PC·가상 PC에서의 확인과는 다릅니다.**
- 다음은 직원 PC에서 확인해야 합니다:
  - SmartScreen·백신 반응
  - 기관 프록시
  - 실제 한글 사용자 계정 이름 경로(runner에서는 한글 폴더 이름으로 흉내만 냈음)
  - 고배율 화면에서 런처 창 모양
- 런처 설정 창의 버튼 클릭은 자동 시험하지 않았습니다. 같은 기능(키 저장·삭제, 비밀번호 저장)은 명령 옵션으로 시험했습니다.

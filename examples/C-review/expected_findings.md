# 예제 C 기대 확인 목록 — 기존 문서 검토 (가상 업체 제출본)

네 파일에 **일부러 넣은 오류**와, 검토 엔진(규칙 기반, AI 호출 없음)이 실제로 내는 결과입니다.
2026-10-30에 `backend/tests/test_examples.py`로 실제 실행해 확인했고, 이 테스트가 매번 같은 결과를 확인합니다.

## 투입 방법(실제 앱)
1. 첫 화면 **기존 문서 검토하기** → 이름 입력 → **만들기**(→ '6 검토·추천' 단계가 열림)
2. **2 자료·질문**에서 파일마다 '문서 종류'를 고르고 올리기
   - `vendor_task.txt` → 업체 과업지시서·제안요청서
   - `vendor_design.txt` → 업체 설계서
   - `vendor_fp.xlsx` → 업체 FP 산정표 (저장소에는 `vendor_fp.csv` 원본. 화면·시연판에서 받으면 같은 내용의 엑셀)
   - `vendor_cost.txt` → 업체 금액 산출서
3. **6 검토·추천** → **검토 실행** → 판정 버튼(확인 일치·차이 발견·확인 필요·근거 부족)으로 걸러 보기

## 넣어 둔 오류 → 탐지 결과
| 넣어 둔 것 | 기대 판정 | 위치 |
|---|---|---|
| 과업지시서의 SFR-005(대기자 자동 승계)가 설계서·FP 산정표에 없음 | **차이 발견**(요구사항 누락) | vendor_task.txt 6줄 |
| FP 산정표 '과정별 통계' EO 가중치 5.0(간이법 기준 5.2) | **차이 발견**(FP 가중치) | vendor_fp.xlsx F8 |
| '신청 내역 조회' EQ가 두 줄 | **확인 필요**(FP 중복) | 9·10행 |
| 기재 합계 48.2, 행 합계 45.2 | **차이 발견**(FP 합계) | F11 |
| 부가세 3,285,915원(공급가액 10%는 3,165,915원) | **차이 발견**(부가세) | vendor_cost.txt 13줄 |
| "기타 필요한 기능은 협의하여 제공" | **확인 필요**(범위 불명확), SFR-099도 설계서에 없어 요구사항 누락으로 함께 표시 | vendor_task.txt 10줄 |
| 인사시스템 연계·동시접속 응답시간 문장 | **확인 필요**(연계 조건·성능·보안 — 문서로 확정 불가) | 과업지시서·설계서 |
| 금액 문서의 '서버 장비' 문장 | **확인 필요**(장비 포함 여부) | vendor_cost.txt 15줄 |

일치로 나와야 하는 것: 단가(605,784원, 등록 기준과 같음), 개발원가 산식(FP×단가×보정계수), 부가세 별도 합계, 총액(=공급가액+기재 부가세).
이윤은 이윤율 기준 원문을 확인하지 못해 적정성을 판정하지 않고 **확인 필요**로만 둡니다.

## 탐지하지 못하는 것(이 예제로 확인한 한계)
- 이름이 다른 중복(예: '교육 신청'과 '신청 등록')은 잡지 못합니다. 같은 이름·유형만 '중복 의심'.
- 요구사항 누락은 **요구사항 ID**(SFR-001 등) 대조입니다. ID가 없는 문서는 ID 대조를 하지 않고 '근거 부족'으로 남깁니다.
- 장비는 **표현**으로만 찾습니다. 이 예제처럼 "넣지 않음"이라고 써도 확인 필요로 표시합니다(사람이 문장을 보고 판단).
- 문서 내용이 사업에 맞는지(기능 설계의 타당성), 실제 성능·연계·보안 충족은 문서만으로 판단하지 않습니다.
- 간이법 표라서 DET·FTR 기반 가중치 재계산(정통법)은 이 예제에 없습니다.

검산·검토 '일치'는 문서끼리 숫자가 맞는다는 뜻이지 설계가 타당하다는 보증이 아닙니다.
